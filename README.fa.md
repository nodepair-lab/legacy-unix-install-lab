# نصب SCO OpenServer 5.0.7 روی سخت‌افزار قدیمی

> 🇬🇧 [English version](README.md)

یک کار عملی برای نصب **SCO OpenServer 5.0.7** روی یک کامپیوتر قدیمی، همراه با مشکلاتی که در مسیر پیش آمد و یک مشکل که هنوز باز است: ارتباط IP.

| بخش | وضعیت |
| :--- | :--- |
| نصب | ✅ کامل شد. سیستم تا خط فرمان بالا می‌آید. |
| کارت شبکه و درایور | ✅ کارت شناسایی شد، درایور نصب شد و اینترفیس با آدرس IP در حالت `UP` است. |
| ارتباط IP (ping) | ❌ حل نشد. ARP کار می‌کند ولی ICMP echo جواب نمی‌گیرد. |

## هدف

نصب یک سیستم یونیکس تجاری کلاسیک روی سخت‌افزار واقعی، شناخت نصب‌کننده و فرایند بوت آن، و وصل کردن ماشین به شبکه.

## محیط

| مورد | جزئیات |
| :--- | :--- |
| سیستم‌عامل | SCO OpenServer 5.0.7 |
| ماشین مقصد | کامپیوتر واقعی و قدیمی (پردازنده‌ی AMD تک‌هسته) |
| تست اولیه | یک ماشین مجازی |
| سیستم‌های مقابل برای تست شبکه | یک لپ‌تاپ ویندوز و چند ماشین مجازی |

## مراحل نصب

1. دانلود ISO نصب از سایت سازنده.
2. تلاش برای ساخت فلش بوت‌یبل با چهار ابزار مختلف. سیستم هیچ‌کدام را بوت نکرد.
3. رایت ISO روی CD و بوت از درایو نوری. نصب‌کننده بالا آمد.
4. تغییر حالت SATA در BIOS به **IDE**.
5. امتحان چند پارامتر در پرامپت بوت هنگام عیب‌یابی شناسایی دیسک.
6. وارد کردن اطلاعات لایسنس (اینجا مستند نشده است).
7. انتخاب نصب تازه با مجموعه‌ی نرم‌افزار استاندارد دسکتاپ، استفاده از بررسی سریع سطح دیسک، تعیین رمز root و اجرای نصب بدون دخالت.
8. نصب تمام شد و سیستم به خط فرمان رسید.
9. نصب درایور شبکه، بالا آوردن اینترفیس و اجرای تست‌های شبکه.

## مشکلات و نتیجه

| مشکل | نتیجه |
| :--- | :--- |
| فلش بوت نشد | با استفاده از CD حل شد. |
| `No root disk has been detected` | SSD/SATA شناسایی نشد. تغییر BIOS به IDE، تعویض کابل و پورت و چند رشته‌ی بوت جواب نداد. با استفاده از یک هارد IDE (HDD) دیسک شناسایی شد. |
| بررسی سطح دیسک بسیار کند | روی یک دیسک بزرگ بیش از نیم ساعت طول کشید. با حالت سریع و غیرمخرب قابل‌تحمل شد. |
| هشدارهای تکراری timeout دیسک | چند بار و در مراحل مختلف تکرار شد. نصب در نهایت کامل شد. علت قطعی مشخص نیست. |
| `idinstall: Cannot copy file - read/write failed` | نصب‌کننده چند گزینه برای ادامه داد. نصب در نهایت کامل شد. |
| `Error on Fixed Disk (minor 0), blkno = 0` | هسته نتوانست سکتور ۰ را بخواند. بعد از تغییرات دیسک و BIOS نصب کامل شد. |
| کارت شبکه‌ی داخلی برد | به‌سادگی راه نیفتاد. جزئیات ثبت نشده است. |
| یک کارت شبکه‌ی PCI دیگر | در خروجی `hwconfig` دیده نشد. |
| D-Link DFE-530TX+ | با نصب دستی درایور بالا آمد و آدرس IP خصوصی گرفت. |
| **ping جواب نمی‌دهد** | **حل نشد** (بخش بعد). |

## مشکل باز: ping

- دستور `arp` روی SCO آدرس MAC سیستم مقابل را نشان می‌دهد، پس لایه ۲ کار می‌کند.
- ping در چهار حالت جواب نگرفت: اتصال مستقیم به لپ‌تاپ ویندوز، از طریق مودم، به ماشین مجازی اوبونتو و به یک ماشین مجازی SCO دیگر.
- چند کارت D-Link مختلف نتیجه‌ی یکسانی دادند.
- سلامت کارت‌ها روی همین کامپیوتر با بوت یک ویندوز Live تأیید شد.
- ICMP در فایروال سیستم مقابل باز بود.

علت پیدا نشده است. به نظر می‌رسد به ترکیب این کامپیوتر و درایور D-Link روی SCO مربوط باشد.

## آنچه یاد گرفتیم

- SCO OpenServer 5.0.7 با SSD و حالت SATA مشکل داشت. با حالت IDE و یک هارد IDE (HDD) دیسک شناسایی شد.
- بررسی کامل سطح روی دیسک بزرگ بسیار کند است و گزینه‌ی سریع قابل‌تحمل است.
- «اینترفیس بالا آمد و IP گرفت» با «ارتباط IP برقرار است» یکی نیست. باید لایه ۲ (ARP) و لایه ۳ (ping) را جدا بررسی کرد.
- هر ادعایی باید با خروجی واقعی دستگاه تأیید شود. حدس‌ها، مثل اطمینان به درایور بومی بعضی کارت‌ها، غیرقابل‌اعتماد از آب درآمدند.
- ابزارها و دستورهای استفاده‌شده: `hwconfig`، `netconfig`، `ifconfig -a`، `arp` و `custom` (برای نصب درایور).
- پرامپت `Boot:` دستورهایی مثل `ls` را می‌پذیرد.

## نکات
